How this is published

GitHub Actions builds this site on every push to feature/execution-07-premium-web and publishes it with GitHub Pages. The URL is stable and outlives any editor session. The build reads only files already committed to the branch, so the preview can never show something the repository does not contain.

Hosting requirements for a full-stack preview

A full-stack preview needs a host that can run a long-lived Node process and a PostgreSQL database. GitHub Pages serves static files only and cannot run either. The exact requirements are:

ComponentRequirement
APINode 22, a long-lived process, health-checked; secrets for JWT_ACCESS_SECRET, JWT_REFRESH_SECRET and MFA_ENCRYPTION_KEY
DatabasePostgreSQL 17 with prisma migrate deploy and a seed run; isolated from production
Customer and admin appsNode 22 build of two Next.js apps, each on its own origin
NetworkingHTTPS on both origins; CORS_ORIGINS set to them; the refresh cookie scoped to /api/v1
IsolationSeparate database, separate secrets, no production credentials or services

Candidate hosts that meet this: a container host (Fly.io, Render, Railway), a small VM, or a Kubernetes namespace. Each needs an account and, for private previews, a token. Until one is configured, this static preview is the permanent, verifiable artifact.
